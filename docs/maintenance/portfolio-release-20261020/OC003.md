# OC003 — expose Keep submission and status in OpenClaw

Status: provisional implementation candidate; unconfirmed. [Plan](INDEX.md) · [Research](RESEARCH.md). OC001 supplies the exact supported OpenClaw SDK/profile and handoff; OC002 supplies enforced restricted ingress; CS002 supplies the selected account-role runtime. This ticket delivers a working client and combined installed candidate, not an alternate solver.

Implement a small native OpenClaw tool plugin for the one admitted repository workflow: submit a user goal and retrieve its existing Keep job/wait/proposal status. Use the installed version's supported registration and tool allowlisting/configuration. Forward to the existing Keep gateway under OC002's narrow credential; use a trusted configured endpoint, shallow validated inputs, existing cancellation signals and bounded responses. Never accept an arbitrary URL, shell command, source path, auth value, approval or privileged route from model arguments.

Retain stable request identity through actual OpenClaw tool/restart context per OC001. On a lost response, inspect/reuse the prior submission rather than create another request. Print the run/job identity, real status, relevant test/diff evidence and the human next action; waiting/failed/uncertain states are not success. No persistent polling daemon, new model orchestration, global plugin registration, ClawHub publication or modification of Effie/Plutarch/other running instances.

Acceptance:

- The exact selected OpenClaw runtime loads/discovers the packaged tools and dispatches them through the real supported plugin surface. A controlled model-backed Keep fixture reaches its approval hold, then produces a tested proposal only after the separate human action. A mocked registrar or HTTP-only request is insufficient proof of OpenClaw compatibility.
- Model-visible schemas/results/logs never expose the owner token, Codex auth or integration credential; only trusted plugin configuration supplies the narrow credential. No tool grants approval/merge/config or general shell/HTTP access. Invalid input, disallowed endpoint/project, wrong credential and unavailable Keep produce bounded errors/holds without fallback execution.
- Duplicate/lost-response and fresh-process status retrieval preserve OC002's durable job identity without extra dispatch. Cancellation/local closure does not claim remote work stopped. Keep's direct CLI continues to work against the same engine.
- Ship the minimal plugin artifact and operator-owned example profile/config instructions alongside the candidate using the existing project release layout where practical. Record Keep runtime/package and OpenClaw/plugin version/hash. Declare any necessary SDK/peer/build dependencies for review; add none to Keep's core and install none on the shared host without applicable authorization.
- Build/install a clearly labeled combined candidate with the OC002/CS002 runtime and plugin. Its actual controlled consumer passes in an owned disposable OpenClaw fixture; retain source and artifact identities for PL002/CS003. This is not the final release or genuine model success.
