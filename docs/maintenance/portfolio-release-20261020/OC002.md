# OC002 — restrict an OpenClaw caller to admitted submission and status

Status: provisional implementation candidate; unconfirmed. [Plan](INDEX.md) · [Research](RESEARCH.md). Depends on OC001's actual credential, project scope and original-principal/human-approval contract. Does not depend on a successful live Codex generation.

Problem: passing Keep's current personal gateway token to an external agent grants owner authority. Omitting approval from its advertised tool list alone cannot enforce submission-only access. Implement one restricted caller operation through the existing project runtime and authentication/authorization seams; preserve ordinary owner CLI and existing organization boundaries.

Scope: admit only the operator-bound repository/project and validated repository goal with approval-required behavior, durable idempotent submission, and bounded status/proposal projection for the caller's own work. Reuse POST /project, project/job projections, existing journal and RBAC/custody where supported. Enforce the restriction on the trusted ingress, including direct requests outside the plugin; do not build a second project runtime, generic identity provider or generic HTTP forwarding endpoint. OC001 must select the concrete installed configuration/credential interface before implementation; no invented endpoint contract is prescribed here.

Acceptance:

- The restricted credential submits permitted work and retrieves its job/wait/proposal state. Returned data excludes credentials, private unrelated session history and owner-only state. Authenticated caller context is server-bound; model-provided identity, path, posture or project fields cannot widen it.
- Direct attempts to resume/approve, merge/revert, change configuration, grant permissions or inspect unrelated jobs refuse before effect. Missing/invalid/expired/revoked credentials refuse. Existing owner and organization cases retain their applicable behavior; do not simulate an organization identity to prove owner support.
- An authorized human can approve the exact pending generation request through the chosen supported handoff, preserving original caller attribution/grant and command custody. Wrong/declined/stale approval, changed source binding or revoked caller prevents execution. The restricted agent cannot approve itself by knowing a decision ID.
- A repeated identical submission identity returns the existing durable job without a second dispatch, including after restart/lost response. A different request under that identity conflicts. Uncertain work remains held; no refunds, silent new-key replay or automatic remote retry.
- Focused gateway/RBAC/project command/journal tests exercise the originally unsafe authority path and a useful permitted request, using controlled providers. Record actual effects and original-principal behavior. No genuine account call or shared service change is needed to confirm this scoped operation.
