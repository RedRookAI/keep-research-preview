# PL006 — interrupt one owned job without disrupting another

Status: provisional implementation/qualification candidate; unconfirmed. [Plan](INDEX.md) · [Research](RESEARCH.md). OC003 supplies the installed combined candidate; reuse existing job cancellation, process isolation, project separation and configured limits. No genuine model call is needed.

Outcome: a stopped, timed-out or failed project stays bounded to its own work and leaves another owned control job intact. This directly demonstrates safe operation in a shared environment without using any other real instance as a test target.

Inspected seams: src/session/project_runtime.ts, src/session/project_job_journal.ts, src/infra/process_isolation.ts and test/project_runtime.test.ts, test/concurrency_governor.test.ts, test/fleet_shared_resource.test.ts. Stop requests and child close do not prove all descendants or a remote provider stopped. Distinguish in-product time/output/admission bounds from separately configured outer CPU/RAM/PID controls; do not advertise an aggregate memory/disk ceiling that Keep does not enforce.

Scope: run two small owned controlled jobs/fixtures under the already authorized outer test profile. Trigger one cancellation and one configured bound/failure at the relevant existing path; reuse equivalent unchanged tests rather than multiply a matrix. Check actual job/process/artifact state and the unaffected control. Make only a demonstrated scoped repair to ownership/cancellation/bound reporting; no host-wide limiter, cleanup daemon, hook or scheduler rewrite.

Acceptance:

- Cancel or time out job A through the supported control. Its state records actual stopped/failed/uncertain disposition and current owned activity; job B continues its expected useful work with unchanged source/state/authority. No signal targets an unrelated process group, gateway or service.
- Configured time/captured-output/admission limits refuse or stop at their actual supported boundaries, with accurate diagnostic results. An unresolved child/group/remote outcome stays unconfirmed and blocks unsafe replay; local closure is not described as remote cancellation.
- Fresh-process inspection preserves each job's separate identity, submission/reservation history and pending decisions. Switching jobs or restarting does not grant approval, reset cumulative work or merge state between them.
- Record actual configured controls and remaining unqualified aggregate-resource guarantees. Existing direct CLI, OpenClaw status and ordinary cancellation behavior remain usable; error messages distinguish local process status from remote uncertainty.
- Save focused tests and the installed controlled consumer evidence for final CS004. This is local profile evidence, not fleet-wide isolation, every descendant's termination or production multi-tenant qualification.
