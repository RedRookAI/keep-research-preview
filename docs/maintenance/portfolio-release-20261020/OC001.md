# OC001 — define the OpenClaw request and human-decision handoff

Status: actionable investigation candidate; unconfirmed. [Plan](INDEX.md) · [Research](RESEARCH.md). OpenClaw is required. Resolve how to implement the smallest supported client using Keep's existing engine; do not reopen whether it belongs in the project.

Known entry points: src/gateway/http_gateway.ts provides POST /project with background/idempotency support, GET /project and /project/jobs, POST /project/resume and /project/merge. src/session/project_command.ts binds work to its original principal; resume checks that identity/grant. Personal gateway authentication currently defaults to OWNER. The existing src/mcp/gateway_mcp.ts facade is not qualified wire transport and includes broader approval tools. Static src/compat/openclaw_adapter.ts does not implement runtime integration.

Deliver a short implementation contract at these actual seams:

- Locate an existing accessible OpenClaw distribution/source suitable for an owned disposable fixture, record exact version/revision and supported plugin/tool registration. Current online docs alone do not pin the installed SDK. Do not inspect other claws' credentials or change their configuration. If no suitable fixture is available, name the missing artifact/permission instead of installing another service.
- Prefer a thin native request/status tool plugin over a new agent loop or unqualified MCP wire server. OpenClaw routes user intent and status; Keep continues Codex generation, workspace/testing/proposal and decision handling. The direct CLI remains intact.
- Specify the narrow authenticated caller: allowed repository/project, submission and own-job inspection, expiry/revocation and caller binding using existing authority mechanisms where possible. A token that defaults to OWNER is not a restricted integration credential. Do not turn OpenClaw session/channel names or model arguments into trusted Keep identity or invent enterprise tenancy for a local owner.
- Resolve the human generation-approval/resume handoff for agent-originated work without breaking NativeProjectCommand's original-principal/grant fence. Identify a supported explicit delegation/approval binding or the smallest missing seam. Merely swapping principals, forwarding the owner's token or suppressing the custody check is not a remedy.
- Map stable request identity/idempotency and status recovery to Keep's existing durable job journal. Define handling of a lost submission response, conflicting reused key and restart/uncertain work; no blind retry under a new key.
- Specify the example OpenClaw tool/workspace profile that cannot directly write the source, approve its own request, read human/account credentials or call another privileged gateway/tool path. State the trusted-host/plugin assumption and the evidence needed for any stronger boundary. Reuse existing owned isolation; no host/global enforcement change is authorized.

Acceptance: a dated note names actual interfaces, chosen version/artifact, role/credential and approval handoff, the minimal OC002/OC003 changes, useful/adverse checks, and remaining gaps. Consult current primary docs and the focused OpenHands comparison in RESEARCH.md; do not run another broad research project. If an essential contract cannot be resolved statically, state the exact safe probe and its required authority. No generation or active-claw deployment is performed. Confirmation establishes this decision deliverable only; unresolved integration/runtime acceptance remains provisional.
