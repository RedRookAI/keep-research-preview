## Decision and limit

The cheapest supported path is documentation repair plus finishing the existing account/installed workflow. Controlled security regressions reuse ordinary deterministic fixtures; one real model task tests integration/usefulness, not comparative security effectiveness. A historical public task with an existing frozen baseline is adequate for that narrow check if retained honestly. Do not grow another benchmark suite, repeat successful unchanged qualifications, or invent runtime fixes from an unknown cause.

The material unresolved decisions are explicit milestone activation, adequate test resources, authority for a further native account attempt despite retained uncertainty, and the CS008 effective native contract. Later integration/release tickets stay provisional. Research can be reused until a changed CLI, interface, dependency/advisory or failed check supplies a concrete reason to update it.
