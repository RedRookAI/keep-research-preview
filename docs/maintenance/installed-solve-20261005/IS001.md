## Research

Actual consumer audit: packaged main never supplies CliDeps.solve, so advertised solve always refuses, even with a configured repository. Project already captures provider/repository/test configuration, materializes a workspace, requires owner or organization authority, runs tests, records a proposal and exposes explicit approval/merge controls. Reuse that runtime rather than adding a second solver pipeline. Preserve injected SolveFn for existing library consumers.

Primary prior art reopened today: [OpenCode documentation](https://opencode.ai/docs/) connects setup, repository use, requested changes and undo; [Aider usage](https://aider.chat/docs/usage.html) connects repository changes, diff and undo. The inference for Keep is a working configured command followed by review controls, not a new installer, provider recommendation or a claim of equivalent model quality.

Existing installed SG31 fixtures demonstrate controlled OpenAI-compatible HTTP responses reaching the packaged project runtime. Prompt-echo KEEP_PROVIDER=local is an opaque fixture and cannot establish useful model behavior. Existing required-jail and native custody checks must remain intact. A proposal's human-merge or other authority refusal remains a refusal even after a CLI approve request.
